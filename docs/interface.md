## 1. 系统结构与通信拓扑

```
            TCP (端口 9000)                      TCP (端口 9000)
  EMS 主站 B ═════════════════╗      ╔═════════════════ 风机控制器 C (单片机)
  (调度决策, 5s)               ║      ║                  (桨距/启停, 1s)
                              ▼      ▼
                        ┌─────────────┐   串口        ┌──────────┐
                        │ 电网模拟器 A │◄────────────►│ C 上位机  │
                        │ (仿真+时钟)  │  (C 内部链路,  │ (wind.db)│
                        └─────────────┘   不在本文档)  └──────────┘
```

**三条铁律:**
1. **B 与 C 之间无直接链路**,一切数据经 A 中转;
2. A 内部"通信进程"与"计算进程"不直接通信,只通过 `grid.db` 交换(本文档不涉及);
3. **A 是唯一时钟源**,仿真时刻(sim_time, 秒)由 A 产生,报文里的时间一律用 sim_time。

## 2. RTU 划分与寻址规则

### 2.1 RTU 划分

| RTU 编号 | 设备 | 维护方 |
|---|---|---|
| R01 | 风电机组 WT | 数据由 A 计算/汇总,含 C 回传量 |
| R02 | 柴油发电机组 DG | A 仿真 |
| R03 | 电网与负荷 LD | A 仿真 |

### 2.2 寻址规则(重要)

**一个点的唯一地址 = RTU号 · 四遥类别 · 点号。**

- 四遥类别(在 JSON 里用 `type` 字段):`YC` 遥测 / `YX` 遥信 / `YK` 遥控 / `YT` 遥调;
- **点号在每个 (RTU, 类别) 内独立从 1 编号,不做全局连续**;
- 报文 Key(如 `WT_ACT`)是点的人类可读名,DB 点表与报文解码都以 (rtu, type, point) 为准,Key 仅用于日志/界面显示。

### 2.3 值编码

| 类别 | JSON `val` 类型 |
|---|---|
| YC / YT | JSON 数值(number,默认浮点) |
| YX / YK | JSON 整数(integer,0/1 类状态量) |

> v0.3 取消原"float32 大端"的二进制编码——JSON Lines 直接承载 IEEE 754 双精度,Python `json.loads` 默认即 float64,精度对本课设远超需求。

### 2.4 数据质量码(quality)

YC 在 DB 中有 `quality` 字段(0=好,1=坏)。JSON 中:
- **`val: null` + `q: "BAD"`** 表示坏值(通道未初始化、采集失败、C 离线等);
- 正常值 `q` 字段可省略,缺省视为 `"GOOD"`;
- **不**再使用二进制 NaN 编码(JSON 标准不支持 NaN 序列化,B/C 直接 `if val is None` 判坏即可)。

## 3. 四遥点表(与 schema.sql v0.3 种子数据一致)

### 3.1 R01 风电机组

**遥测 YC(5 点)**

| 点号 | Key | 名称 | 单位 | 量程 | 变位死区 | 来源 |
|---|---|---|---|---|---|---|
| 1 | `W_SPD` | 风速 | m/s | 0~40 | 0.1 | A(曲线) |
| 2 | `WT_ACT` | 风机有功出力 | kW | 0~100 | 0.5 | A(模型算) |
| 3 | `WT_PITCH` | 当前桨距角 | ° | 0~90 | 0.5 | A(桨距伺服循 C YT2 执行) |
| 4 | `WT_AVAIL` | 可用功率 | kW | 0~100 | 1.0 | A(模型算) |
| 5 | `WT_P_SET_ACK` | 功率设定值(回显) | kW | 0~100 | 0.5 | EMS 遥调回显 |

> **注(2026-09-09 方案B)**: R01:4 可用功率由 A 按风功率曲线自算(欠额定 ∝v³,
> 额定以上封顶), 是"风速允许发多少"的理论上限, **不受 YT1 限功率影响**。
> C 无需回传该量。限功率时注意区分: R01:4 = 可用(只看风速), R01:2 = 实际
> (受桨距折减/限功率约束)。
> **注(2026-09-09 开放 C 参与)**: R01:3 桨距角 = A 桨距伺服循 C 的 YT2 设定
> 转到位后的当前值(未接管时 A 自演为 0° 全迎风)。C 接管期间 R01:2 =
> 可用功率 × η(桨距), A 不再电子钳位 —— 闭环生效说明见 YT2 那行下面。

**遥信 YX(3 点)**

| 点号 | Key | 名称 | 取值 |
|---|---|---|---|
| 1 | `WT_RUN` | 风机运行状态 | 0=停机, 1=运行 |
| 2 | `WT_FAULT` | 风机故障标志 | 0=正常, 1=故障 |
| 3 | `WIFI_STA` | 通信状态 | 0=断开, 1=连接 |

**遥控 YK(1 点)** / **遥调 YT(2 点)**

| 点号 | Key | 名称 | 取值/范围 | 流向 |
|---|---|---|---|---|
| YK1 | `WT_START` | 风机启停指令 | 0=停机, 1=启动 | 见 §6.3(权威待拍板) |
| YT1 | `WT_P_SET` | 功率设定值 | 0~额定功率(100) | EMS→A→风机 |
| YT2 | `WT_PITCH_SET` | 桨距角设定值 | 0~最大桨距角(30) | 风机控制器→A |

> **桨距闭环已生效(2026-09-09 开放 C 真实参与)**: C 每 1s 发一次 YT2 即"接管"
> 桨距。A 收到后**立即**把实际桨距置为设定值(2026-09-10 删掉 6°/s 伺服限速, 无惯性),
> 实际出力 = 可用功率 × η, 折减 **η = 1 − β/30**(β=0° 全迎风满发, β=30° 全卸荷≈0, 0~30 线性)。
> C 接管期间 A **不再**替 EMS 电子钳位 YT1 —— 实际功率能否贴住 EMS 设定,
> 完全取决于 C 算的桨距准不准(这正是内层闭环的演示点)。
> C 断发 **>5s**(真实时间)后 A 自动收回控制权, 恢复按 EMS 限功率钳位(防 C 掉线失控)。
> C 侧如何由风速+设定反算桨距, 见 §5.2 算法建议。

## 4. TCP 报文协议 v0.3(JSON Lines + code)

### 4.1 帧格式(JSON Lines)

每条消息 = 一个 JSON 对象,以 **换行符 `\n` 结尾**。一行即一帧:

```
{<JSON 对象>}\n
```

- **字节序 / 大小端**:JSON 字符串无所谓,但**消息体用 UTF-8 编码**(允许中文备注);
- **消息分隔**:接收方循环 `readline()`,到 `\n` 即切一帧,`json.loads` 解码;
- **单帧上限**:4096 字节(防异常粘包),超过即视为协议错;
- **没有帧头/帧尾/校验**:JSON 自带校验,Python 一行 `json.loads` 失败即可判坏,不需要算 SUM/CRC;
- **TCP 字节流与定界**:接收循环到 `\n` 截一帧;若 4096 字节内仍无 `\n` 则丢弃并清缓冲区(协议错);
- **心跳/重连**:同 §5.3。

### 4.2 顶层必含字段(全局统一)

每条 JSON 消息**必含**以下三个字段:

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | **消息类型码**,全局统一表见下 |
| `ts` | int | 发送时刻,Unix 毫秒(`int(time.time()*1000)`) |
| `src` | string | 发送方角色:`EMS` / `GRID_SIM` / `WT_CTRL` |

### 4.3 code 全局统一表

| code | 方向 | data 字段 | 用途 |
|---|---|---|---|
| `REG` | B/C → A | `{"role": "EMS"\|"WT_CTRL"}` | 连接后第一帧注册 |
| `ACK` | A → B/C | `{"state": "OK", "role": "EMS"\|"WT_CTRL"}` | 注册成功确认 |
| `HEART` | 双向 | `{"sim_time": int}` | 心跳(双向) |
| `PULL_DELTA` | B → A | `{"since": int(上次拉取的 ts 毫秒)}` | 请求自 since 后的变位点 |
| `RESP_DELTA` | A → B | `{"points": [Point...]}` | 变位应答 |
| `PULL_ALL` | B → A | `{}` | 拉取当前全量(用于重连后重建副本) |
| `RESP_ALL` | A → B | `{"points": [Point...]}` | 全量应答 |
| `PUSH` | A → C | `{"points": [Point...]}` | A 推风速 / 功率设定给 C |
| `YK` | B/C → A | `{"rtu", "type":"YK", "pt", "val":0\|1}` | 遥控下发 |
| `YT` | B/C → A | `{"rtu", "type":"YT", "pt", "val":number}` | 遥调下发 |
| `ACK` | A → B/C | `{"rtu", "type", "pt", "state":"OK"\|"REJECT"}` | 执行回执(可带 `reason`) |
| `NACK` | A → B/C | `{"reason": "OVER_RANGE"\|"PARSE_ERR"\|...}` | 协议错 / 执行拒绝 |

> **同名 `ACK` 区分**:注册成功的 ACK `data` 只含 `state+role`;指令回执的 ACK `data` 含 `rtu+type+pt+state`,按 `data` 内容判别。
> **回执 vs NACK**:`ACK` 表示 A 已成功处理;`NACK` 表示拒绝或协议错,必带 `reason`。

### 4.4 Point 结构(在 RESP_*/PUSH 的 `points` 数组内)

```json
{
  "rtu":  "R01",
  "type": "YC" | "YX" | "YK" | "YT",
  "pt":   1,
  "val":  8.5,           // YC/YT 是 number;YX/YK 是 int(0/1)
  "q":    "GOOD",        // 可选,缺省 GOOD;坏值为 "BAD"
  "ts":   1234567890     // 该点的仿真/采集时刻(毫秒),由 A 填
}
```

YC 坏值:`{"rtu":"R01","type":"YC","pt":1,"val":null,"q":"BAD","ts":...}`。

### 4.5 示例报文(直接复制可做单元测试)

以下均为合法 JSON,以 `\n` 结尾传输。

```json
① EMS 注册
{"code": "REG", "ts": 1234567890, "src": "EMS", "data": {"role": "EMS"}}

② 风机控制器注册
{"code": "REG", "ts": 1234567890, "src": "WT_CTRL", "data": {"role": "WT_CTRL"}}

③ A 回复注册确认
{"code": "ACK", "ts": 1234567890, "src": "GRID_SIM", "data": {"state": "OK", "role": "EMS"}}

④ 心跳(sim_time=120s)
{"code": "HEART", "ts": 1234567890, "src": "EMS", "data": {"sim_time": 120}}

⑤ B 拉变位(自仿真毫秒 1234567800 之后的变化)
{"code": "PULL_DELTA", "ts": 1234567890, "src": "EMS", "data": {"since": 1234567800}}

> ⚠️ **`since` 的时钟口径**:必须是**仿真毫秒**(= sim_time×1000, 即你上一次
> 收到的那批 `Point.ts` 里的**最大值**)。**不要**用帧头 `ts`(那是墙钟毫秒,
> 数值约 1.7e12, 比仿真毫秒大几百万倍)——拿帧 ts 当 since 会永远查不到数据,
> `RESP_DELTA` 恒为空。

⑥ A 应答变位: W_SPD=8.5(R01,YC,pt1) + WT_RUN=1(R01,YX,pt1)
{"code": "RESP_DELTA", "ts": 1234567890, "src": "GRID_SIM", "data": {"points": [{"rtu": "R01", "type": "YC", "pt": 1, "val": 8.5, "q": "GOOD", "ts": 1234567890}, {"rtu": "R01", "type": "YX", "pt": 1, "val": 1, "ts": 1234567890}]}}

⑦ B 下发遥调 WT_P_SET=60.0 kW
{"code": "YT", "ts": 1234567890, "src": "EMS", "data": {"rtu": "R01", "type": "YT", "pt": 1, "val": 60.0}}

⑧ B 下发遥控 WT_START=1
{"code": "YK", "ts": 1234567890, "src": "EMS", "data": {"rtu": "R01", "type": "YK", "pt": 1, "val": 1}}

⑨ A 执行成功回执
{"code": "ACK", "ts": 1234567890, "src": "GRID_SIM", "data": {"rtu": "R01", "type": "YT", "pt": 1, "state": "OK"}}

⑩ A 拒绝回执(越限)
{"code": "NACK", "ts": 1234567890, "src": "GRID_SIM", "data": {"rtu": "R01", "type": "YT", "pt": 1, "state": "REJECT", "reason": "OVER_RANGE"}}

⑪ A 推送给风机控制器: W_SPD=10.0 + WT_P_SET=50.0
{"code": "PUSH", "ts": 1234567890, "src": "GRID_SIM", "data": {"points": [{"rtu": "R01", "type": "YC", "pt": 1, "val": 10.0, "ts": 1234567890}, {"rtu": "R01", "type": "YT", "pt": 1, "val": 50.0, "ts": 1234567890}]}}

⑫ 坏值示例: W_SPD=null + q=BAD(通道离线)
{"code": "RESP_DELTA", "ts": 1234567890, "src": "GRID_SIM", "data": {"points": [{"rtu": "R01", "type": "YC", "pt": 1, "val": null, "q": "BAD", "ts": 1234567890}]}}
```

### 4.6 错误与异常处理(协议级)

| 异常 | 接收方处理 |
|---|---|
| 单行 > 4096 字节未到 `\n` | 丢弃,清空接收缓冲,记 ERROR |
| JSON 解析失败 | 返回 `NACK reason=PARSE_ERR`,记 WARN |
| `code` 不在全局表 | 返回 `NACK reason=UNKNOWN_CODE`,记 DEBUG |
| `src` 字段缺失或非预期 | 返回 `NACK reason=BAD_SRC`,记 WARN |
| 必填字段缺失(对单点:rtu/type/pt/val 缺一) | 返回 `NACK reason=MISSING_FIELD`,记 WARN |
| 收到未注册连接的非 REG 首帧 | 断开 socket,记 WARN |
| 心跳超时(§5.3) | A 置 COMM_EMS/COMM_WT=0;B/C 视 A 离线 |

**原则**:协议层不做重传,所有重传由应用层处理(§5.5)。

## 5. 交互流程

### 5.1 EMS 主站 B(拉模式)

```
连接 A:9000 → 发 REG(role=EMS) → 等 ACK
循环:
  每 1s:  发 HEART(sim_time=...) ; 发 PULL_DELTA(since=...) → 收 RESP_DELTA → 更新 ems.db 副本
  每 5s:  调度决策 → ems_control_mode=闭环时:
            发 YT  /  YK (data 里 rtu+type+pt+val)
          → 等 ACK 回执;超时(2s)未回执则重发一次,再失败记 ERROR
断线:    3s 后重连, 重连成功先发 PULL_ALL 重建副本
```

### 5.2 风机控制器 C(单片机,推+回传)

```
连接 A:9000 → 发 REG(role=WT_CTRL) → 等 ACK
循环:
  每 1s:  收 A 的 PUSH(取 data.points 中的 W_SPD、WT_P_SET)
          控制计算 → 发 YT (WT_PITCH_SET, 目标桨距角)   ← 必须每秒持续发
                   (启停按需/按切入切出自判 → 发 YK WT_START)
  每 15s: 发 HEART(sim_time=...)
  每帧:   等 ACK 回执; 断线 3s 重连
```

**C 桨距算法建议(与 A 用同一条折减曲线, 两边数值才对得上)**:

1. 由 PUSH 里的风速算可用功率:`avail = P_rated · min(1, (v / v_rated)³)`
   (风机参数按联调约定: 切入 3 / 额定 12 / 切出 25 m/s, 额定 100 kW);
2. 目标功率 `p_t` = PUSH 里的 WT_P_SET; 没给 / 给得 ≥ avail → 满发, β = 0;
3. 需要折减 `η = p_t / avail`(钳到 0~1), 反解目标桨距 **β = 30·(1 − η)**;
4. 例: 风速 12 m/s(avail=100)+ EMS 限 60 kW → η=0.6 → **β=12°**;
   风速 10 m/s(avail≈57.9)+ 限 30 kW → η≈0.52 → **β≈14.4°**。

> ⚠️ YT2 必须**每秒持续发(哪怕值不变)**: A 靠它的到达判 C 在线, 断发 >5s
> A 就退回自演并按 EMS 限功率钳位 —— 到时 C 的桨距不再生效, 别误以为坏了。
> 📌 第 1 步算出的 avail 只供 C **本地决策**用, 不要回传 —— 遥测 R01:4
> (可用功率)由 A 提供, 两边数值对得上即可。

### 5.4 变位上报策略(建议默认,待确认)

- **遥测 YC**:|新值−上次上报值| > 变位死区(§3 各表)才上报;
- **遥信 YX**:值变化即上报;
- **遥控/遥调**:下发即入库(带 src、state),A 执行后回 ACK;
- 拉模式(PULL_DELTA)与死区结合:B 1s 拉一次,A 只回自 `since` 后有变化的点;**每 10 个周期(10s)B 强制发一次 PULL_ALL**,防止死区+丢帧导致长期漏点。

### 5.5 同步/异步 与 重传策略(应用层)

**B 发指令(YK/YT)→ A 回执(ACK/NACK)** 这一来一回是**同步阻塞**:

- B 发出指令后,等 ACK/NACK,**超时 2s 未回则重发一次**;
- 再 2s 仍未回,标记该指令"执行失败"记 ERROR 日志,UI 标红告警,**不再第三次**;
- B 维护一个"待回执队列"(rtu, type, pt, val, 发包 ts),收到匹配回执后出队;
- 同一 (rtu, type, pt) **同一时刻只允许一条待回执**:新指令覆盖旧的,旧指令视为丢弃(需在 UI 提示)。

**C 同理**。但 C 的指令(WIFI_STA=0 时不下发,在线才下发)。

### 5.6 A 端 TCP Server 并发模型(给 A 实现者)

A 同时接 B(EMS)和 C(WT_CTRL)两个 TCP 客户端,role 不同,**架构上不可混用**:

```
┌─────────────────────────────────────────────────────┐
│                  A 进程 (Python 示例)                  │
│                                                       │
│   TCP Server (主线程)                                  │
│      │                                                │
│      ├─ socket_b  ──> src=EMS   (唯一)                │
│      └─ socket_c  ──> src=WT_CTRL(唯一)               │
│                                                       │
│   注册时按 role 区分,后续按 socket 派发:               │
│     YK/YT 写入 yk_realtime/yt_realtime 排队            │
│     PULL_DELTA/PULL_ALL/HEART → 走对应处理路径          │
│                                                       │
│   RESP_*/PUSH/ACK/NACK 按需发送                        │
│                                                       │
│   + 计算进程(读 grid.db 的 yc_realtime 等)             │
│   + UI 进程(读 grid.db 的所有表)                        │
└─────────────────────────────────────────────────────┘
```

- **实现选型**:Python 推荐 `selectors`(跨平台)或 `asyncio`;**不要**用阻塞 socket + 多线程共享 socket(状态难管);
- **socket 读循环**:每个 socket 一行行 `readline()`,遇 `\n` 切一帧,`json.loads`,try/except 包异常并清缓冲;
- **注册唯一性**:同一 role 只允许一个 socket 在线,新注册踢掉旧(避免 B 端多开);
- **离线检测**:对每个 socket 维护 `last_recv_time`,每个心跳周期(5s)检查一次,>15s 未动则关闭 socket 并置 COMM_x=0。
