## 1. 系统拓扑

风电子站由 **4 个物理部件** 组成，形成两级串行链路 + 一级无线链路：

```
   ┌────────────────┐   USB    ┌─────────────────┐
   │   PC 上位机     │◄────────►│  USB-TTL 串口模块 │
   │  wind_gui.py   │          │  CH340 / CP2102  │
   │  (PyQt6 + db)  │          └────────┬────────┘
   └────────────────┘                 TXD / RXD / GND
                                       │  115200 8N1
                                       ▼
   ┌───────────────────────────────────────────────────────┐
   │              STM32G431RBT6   （主控，170 MHz）          │
   │                                                       │
   │   USART2  PA2(TX) / PA3(RX) ──► 遥测上报 + 参数下发     │
   │   USART1  PC4(TX) / PC5(RX) ──► AT 配置 + TCP 透传      │
   │   PA4     GPIO 输出          ──► ESP8266 硬复位(RST)   │
   │   PA13/PA14 SWD              ──► ST-Link 下载调试       │
   │   PF0/PF1 HSE 24 MHz         ──► 外部晶振              │
   └───────────────────────┬───────────────────────────────┘
                           │ 115200 8N1 + RST + 3.3V/GND
                           ▼
                   ┌───────────────┐   WiFi 2.4 GHz   ┌──────────────┐
                   │   ESP8266     │◄────────────────►│  路由器 / AP  │
                   │  (AT 固件)     │                  └──────┬───────┘
                   └───────────────┘                         │
                                                 TCP 9000    │
                                                             ▼
                                                   ┌───────────────────┐
                                                   │  A 端 电网模拟器    │
                                                   │  TCP Server :9000 │
                                                   └───────────────────┘
```

**三条链路的分工：**

| # | 链路 | 物理介质 | 承载协议 | 说明 |
|---|---|---|---|---|
| ① | PC ↔ STM32 | USB-TTL 串口 | cJSON 文本帧（USART2） | 遥测上报 + 参数下发，**不走网络** |
| ② | STM32 ↔ ESP8266 | 3.3V TTL 串口 | AT 命令 + TCP 透传（USART1） | 建立/维持到 A 端的 TCP 连接 |
| ③ | ESP8266 ↔ A 端 | WiFi 2.4 GHz | TCP（端口 9000） | JSON Lines 协议，见根 `docs/interface.md` |

> **关键认识**：上位机与单片机之间是**独立的一条串口**，而不是走 WiFi。即使 WiFi 断链，上位机仍能收到遥测并下发参数（风机按最后一次收到的风速/设定值运行）。这条设计在固件 `main.c:295-298` 有明确注释。

**未使用的引脚**：本工程仅启用 `NVIC` / `RCC` / `SYS` / `USART1` / `USART2` 五个外设（`WindController.ioc:6-11`），
**没有 ADC、I2C、SPI、定时器、GPIO 输入**。也就是说，风电子站**不接任何物理传感器或执行器**——
风速、功率、桨距角全部来自 A 端的仿真数据，本地只做计算与显示，属于典型的**半实物仿真（软件在环）**结构。

### 3.1 PA4 复位时序（重要）

固件对 ESP8266 的复位是**硬件复位**，这是解决"模块时好时坏"的根本手段：

| 阶段 | PA4 电平 | 持续时间 | 代码位置 |
|---|---|---|---|
| 上电初始化 | 拉**低**（复位态） | — | `main.c:504`（`MX_GPIO_Init`） |
| 复位引脚就绪 | 拉**高**（释放复位） | — | `main.c:542`（`ESP_GPIO_Init`） |
| 发起硬复位 | 低 → 延时 50 ms → 高 | 50 ms | `main.c:546-550`（`ESP_HardReset`） |
| 等待模块重启 | — | 2000 ms | `main.c:570` |

> **PA4 必须接到 ESP8266 的 RST 脚**。若不接，模块只能靠 `+++` 软件退透传兜底（`main.c:572-578`），
> 当模块残留在透传模式且 `CIPMODE=1` 时无法恢复，会出现"TCP FAIL / 一直连不上"。

## 4. 接线说明

### 4.1 电源接线

| 电源网络 | 电压 | 连接对象 |
|---|---|---|
| VCC | **3.3 V** | STM32 的 3.3V 引脚、ESP8266 的 VCC/3V3 |
| GND | 0 V | STM32 GND、ESP8266 GND、USB-TTL GND —— **必须共地** |

⚠️ **三条硬性要求：**

1. **ESP8266 是 3.3 V 器件**，VCC 只能接 3.3 V。接 5 V 会永久损坏模块。
2. **ESP8266 的 RXD 不耐 5 V**。本方案中 STM32 的 I/O 也是 3.3 V，因此**可以直接相连，无需电平转换**；
   但如果换用 5 V 单片机，必须在 TX→ESP RXD 之间加电平转换或分压。
3. **供电电流要够**。ESP8266 在 WiFi 发射瞬间电流可达数百 mA，USB 口直接供电常因压降导致反复重启
   （表现为 `AT FAIL` / `WIFI DISCONNECT` 反复出现）。建议用独立的 3.3 V 稳压（≥500 mA）供电，
   并在模块 VCC-GND 之间并一只 100 µF 电解 + 0.1 µF 陶瓷电容。

### 4.2 STM32 ↔ ESP8266（USART1 + 硬复位）

| STM32 引脚 | 方向 | ESP8266 引脚 | 说明 |
|---|---|---|---|
| **PC4**（USART1_TX） | ──► | **RXD** | 单片机发 AT 命令 / 透传数据 |
| **PC5**（USART1_RX） | ◄── | **TXD** | 单片机收模块回复 / A 端下行数据 |
| **PA4**（GPIO 输出） | ──► | **RST** | 硬复位，**低电平有效** |
| 3.3 V | ──► | **VCC / 3V3** | 供电 |
| GND | ──► | **GND** | 共地 |

**接线要点：**

- **TX/RX 必须交叉**：单片机的 TX 接模块的 RX，反之亦然。接成 TX-TX 是最常见的"就是连不上"原因。
- ESP-01S 一类模块还需 **CH_PD / EN 拉高到 3.3 V** 才能工作（部分底板已内置上拉）。
- 模块上电瞬间会在 **74880 波特** 打印启动横幅，在 115200 下看是乱码 —— 这是**正常现象**，
  固件在 `UART1_Flush()` 中已把它清掉（`main.c:552-559`）。
- `USART1` 的接收中断**故意推迟到透传建立之后才开**（`main.c:687`），避免启动期乱码污染解析。

### 4.3 STM32 ↔ PC 上位机（USART2 + USB-TTL）

| STM32 引脚 | 方向 | USB-TTL 模块 | 说明 |
|---|---|---|---|
| **PA2**（USART2_TX） | ──► | **RXD** | 遥测帧、调试打印（`STM32 Ready` / `AT OK` / `WiFi OK` …） |
| **PA3**（USART2_RX） | ◄── | **TXD** | 上位机下发的配置命令（`set_params` / `get_params` / `set_server` / `get_server`） |
| GND | ──► | **GND** | **必须共地**，否则收到的全是乱码 |
| 3.3 V | ◄── | 3.3V（可选） | 若 USB-TTL 不给 MCU 供电则无需接 |

**接线要点：**

- USB-TTL 模块插到 PC 的 USB 口，在设备管理器里会多出一个 COM 口，**记住这个 COM 号**。
- 上位机**不需要手动选口**：`_find_serial_port()` 遍历所有串口并按描述关键字
  （`ch340` / `cp210` / `stlink` / `usb serial`）自动选中（`wind_gui.py:1023-1031`）。
- **支持热插拔**：串口被拔出后，上位机每 **2 s** 自动重扫端口重连
  （`wind_gui.py:1058-1097`）。拔插后 CH340 可能枚举成**另一个 COM 号**，因此每次
  都重新扫描而不认死旧端口；参数面板第 4 行还有「**重连串口**」按钮可手动立即重连
  （`wind_gui.py:1099-1109`）。
- 重连成功后上位机会自动**先读后写**：先发 `get_params` 把单片机此刻真实生效的
  参数读出来显示，再发 `set_params` 用界面值纠正，两端一致性自动恢复
  （`wind_gui.py:1169-1204`）。
- 若上位机提示「🔴 未检测到串口，每 2 秒自动重试…」，见第 8 节排查表。
- **不要**把 USB-TTL 的 5 V 输出接到 MCU 的 3.3 V 网络（除非板上有稳压）。

### 4.4 ST-Link 下载调试（SWD）

| STM32 引脚 | ST-Link 引脚 | 说明 |
|---|---|---|
| **PA13** | **SWDIO** | 数据线 |
| **PA14** | **SWCLK** | 时钟线 |
| **NRST** | **RST**（可选） | 复位线，建议接上以便可靠下载 |
| 3.3 V | **3.3V**（参考电平） | 仅作电平参考，**不要**用它给整板供电 |
| GND | **GND** | 共地 |

> SWD 只需 2 根信号线即可下载调试（`WindController.ioc:44-47` 已把 PA13/PA14 配置为
> `Serial_Wire`）。烧录在 STM32CubeIDE 中直接点 **Run / Debug** 即可。

### 4.5 接线完成后的自检清单

上线前请逐条打勾：

- [ ] ESP8266 的 VCC 接的是 **3.3 V**，不是 5 V
- [ ] 所有器件 **共地**（STM32 / ESP / USB-TTL / 电源 的 GND 连在一起）
- [ ] USART1：**PC4→ESP RXD**、**PC5→ESP TXD**（交叉）
- [ ] USART2：**PA2→USB-TTL RXD**、**PA3→USB-TTL TXD**（交叉）
- [ ] **PA4→ESP RST** 已连接
- [ ] ESP8266 的 CH_PD/EN 已拉高
- [ ] 3.3 V 电源电流能力 ≥ 500 mA，模块旁有去耦电容
- [ ] SWD 的 SWDIO/SWCLK 未接反、未与其它信号复用
- [ ] 上位机所在 PC 与 A 端 PC 在**同一局域网**

## 5. 串口通信参数

两个串口参数**完全一致**，均为标准 8N1：

| 项目 | USART1（→ ESP8266） | USART2（→ PC 上位机） |
|---|---|---|
| 波特率 | **115200** | **115200** |
| 数据位 | 8 | 8 |
| 校验位 | None | None |
| 停止位 | 1 | 1 |
| 硬件流控 | None | None |
| 引脚 | PC4 = TX，PC5 = RX | PA2 = TX，PA3 = RX |
| 时钟源 | PCLK2（170 MHz） | PCLK1（170 MHz） |
| 中断优先级 | 0（更高） | 1 |
| 用途 | AT 配置 + TCP 透传 | 遥测上报 + 参数下发 |
| 代码位置 | `main.c:398-439` | `main.c:446-487` |

**接收缓冲区设计（影响配置下发帧长度）：**

| 端口 | 缓冲区 | 大小 | 说明 |
|---|---|---|---|
| USART2 | `rx2_buffer` / `rx2_line` | **256 B** | 配置命令较短，256 B 足够（`main.c:68-80`） |
| USART1 | `rx1_buffer` / `rx1_line` | **512 B** | A 端 PUSH 帧含 13 位 Unix 毫秒时间戳，长约 240–260 B，256 B 会溢出导致 cJSON 解析失败（`main.c:82-88`） |

> **不要**把 USART1 的缓冲区改回 256 B —— 这曾是「A PUSH parse ERROR」的根因。

## 6. 网络与地址配置

ESP8266 需连入 **2.4 GHz** WiFi，才能与 A 端建立 TCP 连接。以下参数**编译期固化在固件中**：

| 参数 | 当前值 | 代码位置 |
|---|---|---|
| WiFi 名称（SSID） | `yxtwifi` | `main.c:155` |
| WiFi 密码 | `vqcx3322` | `main.c:156` |
| A 端服务器 IP（默认） | `10.18.134.231` | `main.c:161` |
| A 端服务器端口（默认） | `9000` | `main.c:162` |

**换环境必改**：换实验室/换路由器/换 A 端电脑时，需要修改上述 4 个值并**重新编译烧录**。

### 6.1 运行期修改服务器地址（无需重烧）

IP 与端口支持**运行时由上位机下发修改**，这对应验收要求中的「能够在界面设置通信IP地址」：

- 上位机界面上填写 IP / 端口 → 通过 **USART2** 下发 `set_server` 命令 → 固件更新 `g_server_ip` / `g_server_port`（`main.c:868`）。
- **重启后回到编译默认值**（`main.c:158-160` 的注释明确说明）。
- 为避免重启后丢失，上位机会把地址存进数据库，并在**每次串口连接成功后自动重新推送**。

### 6.2 ESP8266 连接流程（固件自动完成，无需人工干预）

| 步骤 | AT 命令 | 预期回复 | 失败提示 |
|---|---|---|---|
| 0 | （PA4 硬复位，50 ms 低电平） | — | — |
| 0b | `+++`（软件退出透传兜底） | — | — |
| 1 | `AT` | `OK`（重试 5 次） | `AT FAIL (1)` |
| 2 | `AT+CWMODE=1` | `OK` | `CWMODE FAIL (2)` |
| 2b | `AT+CIPMODE=0` | `OK` | — |
| 3 | `AT+CWJAP="<SSID>","<PASS>"` | `GOT IP`（超时 15 s） | `WiFi FAIL (3)` |
| 4 | `AT+CIPSTART="TCP","<IP>",<PORT>` | `CONNECT`（重试 3 次，超时 10 s） | `TCP FAIL (4)` |
| 5 | 发送 `REG` 注册帧 | A 端 `ACK` | `REG FAIL (5)` |
| 6 | `AT+CIPMODE=1` → `AT+CIPSEND` | `>` | — |
| 7 | 开启 USART1 接收中断，进入透传 | — | — |

网络不通时**不会死循环**：`g_link_up = 0`，主循环每秒后台重试整个流程（`main.c:250-259`），
期间**上位机遥测与参数下发照常工作**。

## 7. 时钟配置

时钟树由 `SystemClock_Config()` 配置（`main.c:352-391`），全部参数如下：

| 阶段 | 配置 | 结果 |
|---|---|---|
| 时钟源 | HSE 外部晶体（`RCC_HSE_ON`） | **24 MHz** |
| PLL 输入分频 | `PLLM = /6` | 4 MHz |
| PLL 倍频 | `PLLN = ×85` | 340 MHz（VCO） |
| PLL 主输出 | `PLLP = /2` | **SYSCLK = 170 MHz** |
| AHB 分频 | `AHBCLKDivider = /1` | **HCLK = 170 MHz** |
| APB1 分频 | `/1` | **APB1 = 170 MHz** |
| APB2 分频 | `/1` | **APB2 = 170 MHz** |
| Flash 等待周期 | `FLASH_LATENCY_4` | 匹配 170 MHz |
| 内核电压等级 | `PWR_REGULATOR_VOLTAGE_SCALE1_BOOST` | 支持 170 MHz |

> ⚠️ **⚙ 需按实物确认**：HSE 必须是 **24 MHz**。若开发板板载晶振不是 24 MHz（例如 8 MHz / 16 MHz），
> 则 PLL 参数必须重新计算，否则**串口波特率会整体偏移导致全是乱码**。
> 该值可在 `WindController.ioc` 中的 `RCC.HSE_VALUE` 项核对。

## 8. 上电、烧录与联调流程

**首次部署的完整顺序：**

1. **接线**：按第 4 节连好电源、ESP8266、USB-TTL、ST-Link，逐条对照 4.5 自检清单。
2. **改配置**：核对 `main.c:155-162` 的 WiFi 名称/密码、A 端 IP/端口是否为当前环境的值。
3. **建数据库**：先运行上位机建库函数生成 `db/wind.db`（**必须先建库**，否则上位机写入报错）。
4. **烧录固件**：STM32CubeIDE 打开 `wind/stm32_firmware` → Build（Ctrl+B）→ Run/Debug（调用 ST-Link）。
5. **上电观察**：打开串口助手（115200 8N1）接 USB-TTL，应依次看到：
   ```
   STM32 Ready
   WiFi Init...
   AT OK
   WiFi OK
   TCP -> 10.18.134.231:9000
   TCP OK
   REG OK
   Transparent Mode
   ```
   若在中途停下，按提示的错误码对照第 9 节排查。
6. **启动上位机**：
   ```powershell
   cd wind/scada
   python wind_gui.py
   ```
   上位机自动识别串口并连接（状态栏显示「串口 COMx 已连接」）。
7. **自动同步**：串口连接后约 500 ms，上位机会自动下发一次参数与服务器地址，
   界面上的「单片机实际生效参数（回显值）」区域会被真实值填满。

**日常使用**：只需 5、6 两步（固件无需重烧）。

## 9. 数据链路与点位映射（硬件视角）

理解"哪根线上跑什么"，有助于快速定位故障：

### 9.1 USART2（PC 侧）— 每 1 秒一帧

固件每秒通过 USART2 向 PC 发送一帧 `PUSH` JSON（`main.c:1368-1428`），固定包含 6 个测点：

| 类别 | 点号 | 含义 | 数据来源 |
|---|---|---|---|
| YC | 1 | 风速 `W_SPD` | A 端 PUSH（YC1） |
| YC | 2 | 实际出力 `WT_ACT` | A 端实测值，链路断开时退回本地计算值 |
| YC | 3 | 桨距角 `WT_PITCH` | 同上 |
| YC | 4 | 可用功率 `WT_AVAIL` | 同上 |
| YC | 5 | 功率设定 `WT_P_SET` | A 端 PUSH（YT1） |
| YX | 1 | 运行状态 `WT_RUN` | 本地控制算法 |

- 帧头 `"code": "PUSH"`，`"src": "WT_CTRL"`，时间戳 `ts = sim_time × 1000`（仿真毫秒）。
- 链路判据：`g_link_up && g_a_xxx_ms != 0` → 用 A 的实测值；否则用本地计算值
  （`main.c:1373-1378`）。

### 9.2 USART1（ESP8266 侧）— JSON Lines 透传

| 方向 | 帧类型 | 说明 |
|---|---|---|
| C → A | `REG` | 连接建立后注册身份 |
| C → A | `HEART` | 心跳，约 1 s 一次（否则 A 判定 C 离线） |
| C → A | `YK` / `YT` | 遥控/遥调命令（**仅闭环模式**下发） |
| A → C | `PUSH` | 风速、功率设定等下行数据 |
| A → C | `ACK` / `NACK` | 命令确认 |
| A → C | `HEART` | 心跳，**携带 A 的权威仿真时刻**（`main.c:1208-1214`） |

> **开环/闭环差异**：`g_control_mode == 1`（闭环）时才发送 `YK1` + `YT2`（`main.c:338`）；
> 开环模式下**只发 HEART**，不会向 A 发送控制命令。这一点可用于验收时验证模式切换是否生效。

### 9.3 ⚙ 数值缩放说明（需按固件版本确认）

| 固件版本 | `val` 字段类型 | 上位机处理 |
|---|---|---|
| **当前版本** | 浮点数直传，无 `scale` | 直接使用 |
| 旧版本 | 整数 + `scale` 缩放因子 | 按 `val / scale` 还原 |

上位机已兼容两种格式（`wind_data_receiver.py:79-89`）。若曾听说「遥测值要除以 100」，
那是**旧版固件**的行为；当前固件为浮点直传，**不需要再除 100**。

## 10. 常见故障与排查对照表

| 现象 | 可能原因 | 排查与处理 |
|---|---|---|
| 上位机提示「🔴 找不到串口」 | USB-TTL 驱动未装 / 线未插好 / 模块描述串不含识别关键字 | 装 CH340 或 CP210x 驱动；设备管理器确认 COM 口存在；更换模块或改用带 `USB Serial` 描述的模块 |
| **拔掉 USB-TTL 再插回，上位机一直连不上** | 旧版上位机只在启动时连一次口，拔线后接收线程退出且无任何重连入口 | 现版本已内置**每 2 s 自动重扫重连**（`wind_gui.py:1058-1097`），拔插后无需重启 GUI；也可点参数面板的「**重连串口**」按钮立即重连。若重插后 COM 号变了同样能自动认到 |
| 拔插后**遥测恢复但参数不一致** | USB-TTL 同时给 MCU 供电时，拔插会让 MCU 掉电重启，固件参数回到编译默认值 | 上位机重连后会**先发 `get_params` 读回单片机真实值并显示**，再发 `set_params` 用界面值纠正；日志里可看到「📋 单片机当前实际参数 …」与随后的「✅ 连接后参数自动同步」。⚠ 此功能要求固件为含 `get_params` 命令的版本（`main.c:836-857`），旧固件会静默跳过读回、只做写入 |
| 串口有数据但全是**乱码** | 波特率不是 115200 / **未共地** / HSE 晶振不是 24 MHz | 统一 115200 8N1；确保 STM32 与 USB-TTL 共地；核对晶振频率 |
| 串口无任何输出 | 未上电 / MCU 未运行 / TX-RX 接错 | 测 3.3 V 供电；确认 PA2→USB-TTL RXD 交叉；按复位键 |
| 打印 `AT FAIL (1)` | PA4 未接 RST / 供电不足 / 模块非 AT 固件 | 检查 PA4→RST；用独立 3.3 V ≥500 mA 供电；重新烧写 ESP8266 AT 固件 |
| 打印 `CWMODE FAIL (2)` | 模块残留在透传模式 | 确认 PA4 硬复位电路有效（这是根治手段） |
| 打印 `WiFi FAIL (3)` | SSID/密码错 / 路由器为 5 GHz / 信号弱 | 改 `main.c:155-156`；**ESP8266 只支持 2.4 GHz**；靠近路由器 |
| 打印 `TCP FAIL (4)` | A 端未启动 / 不在同一网段 / 防火墙拦截 / 端口被占 | 改 `main.c:161-162`；确认 A 端 TCP Server 已在 9000 端口监听；关闭防火墙或放行 |
| 打印 `CIPSTART: no reply` | 目标 IP 不可达（多半是 A 端电脑 DHCP 换了 IP） | 在 A 端电脑上 `ipconfig` 查当前 IP，更新为上位机下发的地址 |
| 打印 `REG FAIL (5)` | A 端未运行 / 端口被其它程序占用 | 确认 A 端程序在跑且 REG 处理正常 |
| 链路反复 `LINK LOST, reconnecting...` | A 端主动踢连接 / WiFi 抖动 / 供电跌落 | 查 A 端是否重复注册；加强供电滤波；缩短与路由器距离 |
| 上位机有遥测但**曲线不动** | 数据库未建 / 时间戳异常 | 先运行建库函数生成 `db/wind.db`；查看串口日志确认 ts 是否递增 |
| ESP8266 上电打印一堆乱码后无响应 | 74880 波特启动横幅，属正常现象 | 无需处理，固件已自动清除 |
